## Current and target contracts

The current CLI has `CurrentDocuments` and `InsertDocument` in `pkg/client/documents.go`, and a narrow `internal/documents.Access` for change editors. Change details load current docs; project/epic document navigation, history and details are absent. The app shell still coordinates the change editor, and `internal/documents` has no document screen/model. Preserve P4 ordinary change editors and P5 testcase behavior while adding a shared document feature reachable from every owner.

All document endpoints are POST under `/api/v1/doc`:

| Route | Request JSON | Success | Semantics |
| --- | --- | --- | --- |
| `/list` | `{"ref_id":positive integer,"ref_table":"project"|"epic"|"change"}` | `200` array of full docs | All retained versions for exactly one owner, descending numeric ID. An existing owner with no docs returns `[]`; the backend does not preflight parent existence on read. |
| `/current` | Same owner request | `200` array of full docs | Current versions only, descending ID. Multiple configured types can each be current. Empty is `[]`. |
| `/details` | `{"id":positive integer}` | `200` full doc | Reads historical or current version by document ID, independent of owner. The CLI must reject a row whose returned owner differs from the selected owner before displaying/acting on it. |
| `/insert` | `{"ref_id":positive integer,"ref_table":owner,"doc_type":nonblank configured type,"body":nonblank text,"agent_edit":boolean}` | `201 {"id":positive integer}` | Atomically appends a version; previous same-type current row becomes historical. Backend trims outer body whitespace. Send the editor's exact bytes; do not silently rewrite them client-side. Ordinary human editing sends explicit `false`; the later fixed workflow can use explicit `true` through the same capability. |

Every full row includes numeric `id`, `ref_id`, `ref_table`, `doc_type`, `body`, boolean `agent_edit`, boolean `current`, `created_at`, `updated_at`, and `html`. The backend renders `html` from stored body. Reject missing/wrongly typed required fields, invalid IDs, malformed arrays/IDs, duplicate or out-of-order list rows, wrong owner rows, `current=false` in `/current`, unexpected success statuses or bodies. Preserve HTTP status and underlying causes in typed errors. Each adapter operation performs one context-aware finite-timeout request; no guessed envelope, alternate field, update, or delete route. Backend missing doc/parent, invalid payload/type and failure statuses remain visible. Project configuration supplies separate `project_docs`, `epic_docs`, `change_docs`; absence/empty catalog blocks insertion for that owner but does not block reading existing history. Type values are used exactly as configured.
