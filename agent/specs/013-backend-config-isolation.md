## Evidence and bounded design

At preparation, backend/pkg/config/config.go stores package-global `cfg Config`; `New()` mutates it and also gookit's default singleton through package-level WithOptions/AddDriver/LoadFiles/Decode. `Get()` returns a mutable pointer into shared state. Main calls New/Get then applies port/database flags. Unit tests currently reset both globals between scenarios. This permits repeated loads and caller mutations to contaminate later configuration instances and hides dependency ownership.

The existing dependency github.com/gookit/config/v2 v2.2.9 exposes `config.New(name, opts...)`, instance AddDriver/LoadFiles/Decode and ParseEnv. Module source confirms each instance gets its own options/maps/decoder settings; `New` adds the same JSON driver as the current default, after which the existing YAML driver can be added. Reuse these APIs without upgrading or adding dependencies. Do not use NewGeneric: it enables ParseDefault/ParseTime that current configuration does not enable.

Preferred implementation: `func New() *Config` constructs a fresh local gookit loader with ParseEnv, adds yaml.Driver, loads unchanged relative `config/dev.yaml`, decodes into a zero-initialized local Config, applies the existing defaults and nonempty environment overrides to that instance, then returns its address. Remove package-global cfg and Get after a fresh reference search. Main receives `cfg := config.New()` and otherwise preserves its flag/signal/lifecycle code. Existing loader errors still panic with `apperror.Wrap(err, "configuration")`, preserving cause and startup ordering. No new file-path argument, loader interface, hook, test-only dependency injection or environment flag is needed for these cases.

Keep Config fields/mapstructure tags and Addr/AllowedOrigins contracts unchanged. `applyDefaults`/`applyEnv` may become receiver methods or explicit pointer functions; choose the simplest private representation. Independent returned pointers may be modified by their owners exactly as main currently applies flags. No global gookit configuration is read, reset or modified by production initialization.

R3 owns router/lifecycle separation and must remain intact. Do not duplicate it, add flag parsing abstractions, alter signals, change resource acquisition/cleanup, or move error-handling exits merely to cover main. R1 may already remove the obsolete debug comment; do not restore or count it as new R4 work.

## Acceptance criteria

R4-01 Independent construction: every successful New allocates and returns an independently owned Config and uses a fresh local gookit loader. Remove both backend cfg singleton and Get; no production calls to gookit global WithOptions/AddDriver/LoadFiles/Decode/Reset remain. Main consumes the returned instance explicitly. Two loads with different file contents must not share pointer identity or carry fields from the first into the second, even when fields disappear from the file. Mutating one returned Config cannot change another or future loads. This intended removal of accidental shared-state coupling is the only behavior change.

R4-02 File/decode parity: retain exact relative `config/dev.yaml`, YAML driver, ParseEnv option and mapstructure field names. Missing/unreadable file, malformed YAML and type-incompatible decode errors must still panic as errors wrapped with context `configuration`, preserving underlying causes. Do not silently ignore a missing file, substitute defaults on parse failure, convert panic into nil/config zero value or return-error startup policy, add search paths or change file/environment load ordering. A failed New must not corrupt previously returned instances or leak partially decoded fields into the next successful New.

R4-03 Precedence parity: decode file first, fill empty values with exact existing defaults, then apply only nonempty DATABASE_URL/PORT/CORS_ORIGINS values. Defaults remain ConnectionString `postgresql://localhost:5432/postgres`, Port `8080`, CORSOrigins `http://localhost:8000`. Empty/unset environment values do not erase file/default values; nonempty values remain untrimmed as today. Gookit YAML `${NAME}` and `${NAME|fallback}` interpolation stays enabled before explicit env overrides. CLI nonempty -port/-db overrides remain last; omitted/empty flags preserve the loaded values. Main still loads configuration before flag.Parse, preserving current failure versus help/invalid-flag ordering. Do not move or redesign flags in this pass.

R4-04 Derived accessor parity: Addr keeps an existing leading colon and prepends one otherwise, without adding new validation/trimming. AllowedOrigins splits comma, trims each item and omits blanks, preserving order, duplicate behavior and the current nil slice for an empty/all-blank source. These methods act only on their own Config receiver and reflect intentional owner mutation. Keep application CORS configuration distinct from project-selected database configuration.

R4-05 Meaningful isolation/error tests: replace tests that reset global cfg/gookit state with tests using the normal fixed-path constructor in a temporary working directory. Within one test, load fileA containing all fields, then fileB omitting selected fields or containing {}, without any global Reset; prove defaults rather than old values and prove returned pointer/mutation independence. Include a failed middle load followed by a valid load and verify both earlier objects and new results. Preserve missing-file, malformed-YAML, decode error and underlying-cause assertions. Add explicit environment interpolation, fallback, empty versus nonempty override, and accessor edge cases as needed; do not duplicate covered cases merely to add test count. Each listed acceptance behavior needs a meaningful named assertion.

R4-06 Concurrent independence without global test races: with one immutable temporary config file and a stable environment/working directory set before goroutines start, concurrently construct independent configurations and mutate only each goroutine's own result. Collect results and prove distinct ownership/expected values under the race detector. Do not run t.Chdir/t.Setenv concurrently or repeatedly mutate process environment to fabricate a race; use the same ordinary New API, not test-only constructor parameters. Test setup may change the fixed-path fixture sequentially between scenarios; no parameter exists solely to make tests convenient.

R4-07 Startup and integration parity: update the actual post-R3 main call site and affected legitimate callers/tests after a reference search; no stale New/Get pattern or ignored returned instance remains. Preserve normal startup stdout/stderr/error behavior, file/environment/flag precedence, signal setup and existing router/lifecycle/resource ownership. Run existing startup/lifecycle tests and complete APIHydra campaign against the owned instrumented server. Existing runner passes explicit db/port flags and therefore exercises production overrides; ensure that behavior stays asserted through real successful startup. Do not create new CLI behavior, production failure switches or public test endpoints. Where a subprocess assertion is useful for failure ordering, use the ordinary executable with temporary config; do not add a main seam solely to collect uncovered statements.

R4-08 Scope/verification/reporting: keep the change focused on local loader/instance ownership and corresponding startup injection/tests. ## Test implementation guidance

The existing test already uses t.TempDir/t.Chdir and writes config/dev.yaml; keep that straightforward fixture pattern. Clear the three explicit override variables with t.Setenv for deterministic tests, set interpolation variables intentionally, and never call tests in parallel while changing process cwd/env. A separate within-test goroutine phase can safely read one immutable fixture while cwd/env stay stable. Use channels/WaitGroup and ordinary result assertions; no need to inject a loader interface or add a production filename parameter.

A local malformed YAML sequence `[` proves load/parse error; a `port: [one, two]` fixture proves decode failure; missing config/dev.yaml proves *os.PathError remains in the panic's error chain. Check context and errors.Unwrap/errors.As rather than pinning upstream full prose or stack traces. Preserve previously returned object values across these failures and a subsequent successful default load. Two distinct local constructors should yield distinct addresses even with identical values. No test should rely on gookit.Reset or know private loader maps to prove isolation.

Characterize current ParseEnv interpolation from the installed dependency source/tests if needed, including fallback behavior; do not guess a new syntax or upgrade libraries. All three Config fields are strings, so independent values and pointers are sufficient ownership evidence; there are no shared slice/map fields to invent. Accessor results are derived per call and should preserve nil-versus-empty semantics.
