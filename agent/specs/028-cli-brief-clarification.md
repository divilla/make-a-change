## Boundary and current contracts

The current CLI can create a change with an ordinary user brief and append ordinary documents; it has no `internal/agent` controller or process runner. Add one discoverable fixed workflow for a selected project's new change or an existing selected change. P8 reaches an explicit **brief ready for spec writing** state but does not invoke `spec-write`, `spec-review` or `spec-fix`, create a spec, claim reviewed completion, execute implementation, or publish Git changes. Keep ordinary CRUD/document/health use independent of agent availability.

The backend owns durable data. `POST /api/v1/change/create` accepts `{project_id,ref_uuid?,title,brief}` and returns `201 {id}`; its service requires a nonblank title/brief and selected config containing `backlog` and `brief`, trims outer brief whitespace, and creates the initial current brief. `POST /api/v1/change/details` uses `{id}` and returns the selected change, including its project ID. `POST /api/v1/project/config` uses `{id:project_id}` and returns that project's six arrays. `POST /api/v1/doc/current` uses `{ref_id:change_id,ref_table:"change"}` and returns current versions; `POST /api/v1/doc/insert` accepts `{ref_id,ref_table:"change",doc_type:"brief",body,agent_edit}` and returns `201 {id}`. Inserts append versions and make the previous same-type version historical. `POST /api/v1/doc/list` and `/details` remain available for revision inspection. Do not invent change brief fields, alternate routes, implicit writes, or a transaction spanning these calls. The backend trims outer document whitespace; send exact editor/agent bytes and retain the user's original bytes in the session and operation-owned input file rather than asserting the backend stores untrimmed bytes.

The selected project must provide `change_docs` entries exactly `brief` **and** `spec` for this workflow, and `change_phases` must contain `backlog` for new-change creation. Missing/unavailable catalogs are actionable blockers: no fallback type, fabricated phase, agent launch or premature create. Existing change identity/project must come from a successful details read; current brief must come from its current document read, not a synthesized field. A missing current brief may be supplied by the user and appended with `agent_edit:false` before agent clarification; conflicting/wrong-owner current rows or stale project selection must not be used. Revalidate project/document scope before a write when the workflow's selected entity has changed.

P8 uses only `.mch/default/prompts/brief-rewrite.md` for the first clarification and `brief-resolve.md` after answers; preserve the other three prompt files for P9. The controller supplies explicit brief/context/question/answer input paths and a distinct output path under an operation-owned scratch directory below repository-relative `.mch/tmp/` (create it if absent). Tighten the two P8 prompts to require one bounded structured result: `input_revision`, `rewritten_brief`, `questions` with stable nonblank IDs, concrete text and affected-brief context/text, `unresolved` blocker IDs, and explicit `ready_for_spec` boolean. Every unresolved ID must refer to a question returned in that result. A ready result requires no unresolved blockers or unanswered blocking question; malformed, empty, mismatched-revision, duplicate-ID, contradictory or missing output is an error, never implicit readiness. The controller retains previously answered question/answer pairs across rounds; the agent or process exit cannot discard or silently resolve them. The controller, not the agent or process exit, owns question/answer state and transitions. No arbitrary agent text becomes a shell command or backend field.
