A valid project→epic→change→testcase chain and current change document can support outage reads/failed writes; separate unreferenced records support independent failing deletes. No normal step may modify these records. No implicit ID1, historical schema columns, invalid stored types, constraint removal or table corruption.

At each fresh apih invocation, captures reset: fixed outage/recovery fixture IDs are intentional, request paths remain static, recovery captures are local to that phase. Use retries:-1 for mutation/error files; zero inherits installed retry defaults. Preserve substantive expected_body assertions for reads/errors and explicitly document apih's subset/empty-body limitations; existing unit tests remain authority for exact ID-only create and genuinely empty204 bodies. Normal SQL postconditions and recovery SQL checks run while PG is up and fail with ON_ERROR_STOP. They are not counted as apih-driven backend statements.

A narrow start_database/stop_database helper can reduce repeated flags while preserving visible lifecycle state. Do not introduce a configurable phase framework, optional skip-outage gate, production outage hook or general process manager. One server process and one counters directory make provenance straightforward. pg_ctl -w readiness is authoritative for restart; no unasserted HTTP request should mask the first genuine recovery failure.
